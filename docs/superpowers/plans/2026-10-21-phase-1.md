# Plan de implementación: Fase 1

**Objetivo:** API funcional y probada dentro del alcance aprobado.
**Arquitectura:** routers HTTP, services con transacciones, repositories SQL,
models SQLAlchemy, schemas Pydantic, core de configuración/auth y db de sesiones.
**Stack:** Python >=3.13, FastAPI, SQLAlchemy 2, SQLite, Argon2id, PyJWT, pytest.
**Spec:** ../specs/2026-10-21-phase-1.md
**Ejecución:** directa en esta sesión, autorizada por el usuario; ciclos TDD
por entrega y commits locales; sin push/merge ni pausas por decisiones ya aprobadas.

## Tareas verificables

- [ ] 1. app/main.py, core/config.py, db/session.py, db/init.py, dependencias,
  README y tests/test_foundation.py: configuración sin secreto predeterminado,
  FK por conexión, rollback y arranque sin crear archivos. Ejecutar pytest y commit.
- [ ] 2. models/user.py, schemas/auth.py, repositories/users.py,
  services/auth.py, core/security.py, routers/auth.py y tests/test_auth.py:
  registro, duplicados, hash Argon2id, login, JWT vencido/firma inválida/claims
  faltantes/usuario inexistente. Primero pruebas rojas; luego suite verde y commit.
- [ ] 3. models/dimensions.py, schemas/dimensions.py, repositories/dimensions.py,
  routers/dimensions.py y tests/test_dimensions.py: tres catálogos protegidos,
  vacíos y orden estable. Primero pruebas rojas; luego suite verde y commit.
- [ ] 4. models/polizas.py, schemas/polizas.py, repositories/polizas.py,
  services/polizas.py, routers/polizas.py y tests/test_polizas.py: creación y
  detalle, duplicado, FK, entrada inválida, rollback tras fallo de un ítem
  usando un trigger SQLite real. Primero pruebas rojas; luego suite verde y commit.
- [ ] 5. ampliar consultas y tests/test_queries.py: SQL con filtros, EXISTS,
  count, orden por id, LIMIT/OFFSET; defaults, límites, fechas invertidas,
  páginas vacías, ausencia de duplicados por ítems. Actualizar README y ejecutar
  suite, lint, compatibilidad con copia del esquema real y revisión final.

## Foco de revisión

Pruebas de NULL legado; enteros fuera del rango SQLite; mismo ítem para filtros
combinados; tokens sin expiración; rollback real después de escribir cabecera.
No pruebas sobre la base original. No secretos ni datos en commits.
